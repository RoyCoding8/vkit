# Relations in supplied traces

`infer_trace_relations(root, path, timeout_seconds=20)` translates a captured typed observation bundle into a fixed Daikon data trace, runs the pinned Daikon 5.9.0 engine, and independently checks supported integer relations against every corresponding sample. It never instruments, imports or executes application code. The service trusts the supplied observation identities and values as input data.

The JSON bundle has exactly `version: 1`, `profile`, `variables` and `observations`. `variables` maps short ASCII identifiers to `int` or `bool`. Every observation has `trace_id`, `point_id`, a nonnegative integer `step`, and `values` containing every declared variable exactly once. Steps must strictly increase within each trace and point. Integers must fit signed 64 bits; booleans are encoded as 0 or 1 for the engine.

The `states` profile searches relations among values at each point. The `consecutive` profile searches relations between consecutive supplied observations of the same trace and point. It does not treat events from different traces or points as consecutive. It cannot establish that the recorded events were consecutive in an actual application. Output maps generated variable names back to declared names, including before/after labels for paired observations.

Daikon proposes likely invariants. The installed checker accepts only bounded integer comparisons with addition, subtraction, multiplication and signed integer constants. Every accepted proposal is evaluated with exact Python integers against every relevant supplied row or pair. `OBSERVED_IN_SAMPLES` reports sample and trace counts. A rejected proposal has `COUNTEROBSERVED` and a concrete contradicting row or pair. Unsupported engine expressions remain separately labeled `unverified_engine_candidates`. No engine text is evaluated as Python code. `ANALYZED_SAMPLES` means this bounded discovery and checking campaign completed. It does not assert a universal invariant or complete discovery of every supported relation.

Limits are 2 MiB input/output, 2,000 observations, 16 points, eight variables for states or four variables for pairs, 512 engine candidates, 128 nodes per checked candidate, and two million candidate-node/sample visits. The shared 1–60 second deadline includes execution and replay. The Java process uses a 512 MiB heap and the existing process-tree timeout mechanism. Missing or mismatched service-owned `VKIT_DAIKON_JAR` returns `UNAVAILABLE`; unsupported input returns `UNSUPPORTED`; unfinished execution, output ambiguity, timeout or resource limits return `UNKNOWN`.

Deploy the release with `python scripts/install_daikon_engine.py --output /trusted/daikon.jar`, then set `VKIT_DAIKON_JAR` to that service-owned path.
