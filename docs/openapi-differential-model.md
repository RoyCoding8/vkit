# OpenAPI parser consistency

`inspect_openapi_parser_consistency(root, path, timeout_seconds=20)` compares the model produced by pinned `oasdiff` 1.33.0 when it flattens each captured source file with the model produced when it flattens a JSON encoding of vkit's local parse of that same file. The operation captures the entry document and its repository-local `$ref` closure with the existing OpenAPI reader, then preserves each file's relative path and references in both temporary trees.

The result describes flattened-model consistency only. It does not claim full parser equivalence, validate every OpenAPI rule, or establish how other consumers interpret the source. JSON values are compared recursively with their types preserved, so `true`, `1`, `1.0`, and `"1"` remain distinct. Differences use escaped JSON Pointers; strings carry a bounded preview and exact SHA-256, and arrays or objects carry a canonical JSON SHA-256. The result includes the pinned executable hash, captured source and control hashes, and each flattened output hash.

The operation returns `CONSISTENT_IN_FLATTENED_MODEL` when every captured file produces the same parsed flattened JSON model. It returns `DISAGREEMENT` only when a difference survives a fresh-process replay of both inputs. If replay differs, the result is `UNKNOWN`. A file rejected by `oasdiff` for both representations is `UNSUPPORTED`; malformed output, timeouts, output limits, or unstable process results are `UNKNOWN`. A local parser value that JSON cannot represent, including YAML dates and datetimes, is explicitly `UNSUPPORTED`.

Capture rejects remote references and paths outside the repository. It supports repository-local references and non-recursive YAML aliases through the existing bounded snapshot and parser helpers. YAML 1.1 grammar cases such as `on` and `1e3` are useful controls because the local PyYAML interpretation can differ from the backend's YAML interpretation. Dates are an unsupported control because PyYAML can produce native date objects that have no JSON representation.

The inspection shares the OpenAPI limits: at most 256 captured files, 2 MiB per source or control file, and 16 MiB total. Backend output is limited to 8 MiB per process, returned evidence to 256 KiB, differences to 32 entries, and value previews to 160 characters. The timeout is an integer from 1 to 60 seconds and covers capture, parsing, flattening, and replay.
