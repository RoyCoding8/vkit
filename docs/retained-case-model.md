# Replay retained scenario cases

`replay_retained_cases(root, run_id, before_ref, timeout_seconds=120)` replays one currently approved `ScenarioCheck`. `run_id` must identify a completed scenario-check run whose recorded input snapshot still exactly matches the current checkout; the run may have passed or failed. `before_ref` must be a full lower-case Git commit SHA whose check entry has the same digest as the currently approved check.

The operation captures the exact declared input paths from `before_ref` as the retained bundle and captures only the check's declared subject paths from the current checkout as the candidate. The old and current input path sets must match. Both copies must contain regular Git blobs/files; secret-like, missing, symlink, submodule, or unsupported-mode inputs are refused. Each retained and candidate path is returned with its SHA-256 and file mode. The approved check command must directly name at least one retained non-subject input, and no candidate subject can also be a command input. This keeps the assertion-bearing driver in the retained bundle. The command, required case IDs, and runner configuration come from the digest-matched approved check; callers cannot provide a command or replace the retained harness.

The baseline runs first in a fresh temporary workspace with every declared input from `before_ref`. Candidate execution starts only if that control reports every required case exactly once and all pass. The candidate runs in another fresh workspace, with only its subject files overlaid on the retained inputs. Each run uses the approved dispatcher, environment, and check timeout. The total execution deadline is 30–600 seconds; input capture reuses the existing workload limits of 1,000 files, 1 MiB per file, 16 MiB total, and 8 MiB per report.

Statuses are `REGRESSION` when the clean retained baseline passes and one or more candidate cases fail, `REPLAYED_PASS` when both pass, `BASELINE_FAILED` when the retained control itself reports a required failure, `INCONCLUSIVE` when either execution or report is unusable, and `UNSUPPORTED` when approval, captured bytes, commit, or check-definition preconditions do not hold. Per-case rows contain the literal case ID, result, and observation emitted by the retained driver, along with the corresponding candidate reading. These results apply only to the retained declared inputs and one approved scenario check; they do not establish whole-repository correctness.
