# TypeScript declaration API profile

`compare_contracts` profile `typescript-api` compares a captured old `.d.ts` entry point with a captured new `.d.ts` entry point. The TypeScript 5.9.3 compiler builds the local declaration closure and checks each old exported type and value with its strict assignability relation. This is evidence about the checked declaration types. It does not establish runtime behavior or universal source compatibility; TypeScript includes unsound constructs, and this profile rejects explicit `any` from the compared API.

The Python boundary captures UTF-8 declaration files beneath each entry point's directory. Capture rejects symlinks and reparse points, and applies limits of 128 files, 256 KiB per file, 2 MiB total per side, 10,000 directory entries, and a 60-second maximum. The helper resolves only relative declaration imports inside this captured set. Bare package imports, unresolved/ambiguous imports, ambient module declarations, nonliteral imports, and unsupported declaration forms return `UNSUPPORTED`. Compiler diagnostics in otherwise captured declarations return `UNKNOWN`. An absent, mismatched, or unpinned helper/runtime returns `UNAVAILABLE`.

All previous exported names must remain. Additive exports are permitted. Both type and value meanings are checked for declarations such as classes. Function calls, overload sets, constructors, and interface/class methods are compared in the new-to-old direction: the new declaration must accept old caller inputs and provide old caller outputs. The helper checks method parameter variance explicitly because TypeScript intentionally treats method parameters bivariantly in ordinary assignability. Generic interface, class, and type-alias parameter arity, constraints, defaults, and variance markers are checked; generated strict type-instantiation probes check generic declaration assignability. Generic call/construct signatures, dependent or imported generic constraints/defaults, `any`, namespace merges, and declaration forms outside the explicit helper model are refused rather than treated as compatible.

The helper is invoked with one JSON request on standard input and no caller-controlled arguments. Its installed TypeScript version must be 5.9.3. The service checks the SHA-256 of `helper.cjs` and `package-lock.json`; CI must install dependencies with `npm ci --prefix tools/typescript --ignore-scripts` and configure `VKIT_TYPESCRIPT_HELPER`, `VKIT_TYPESCRIPT_HELPER_SHA256`, `VKIT_TYPESCRIPT_LOCKFILE`, `VKIT_TYPESCRIPT_LOCK_SHA256`, and `VKIT_NODE_BIN`. Node must be v24.16.0. The compiler package lock records the registry artifact integrity. Supported CI is the repository's Ubuntu, Windows, and macOS matrix because this backend uses the pinned Node compiler without a native extension.
