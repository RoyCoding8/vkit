# Paired workload comparison

`compare_workload_cost(root, run_id, before_ref, *, pairs=10, timeout_seconds=600)` compares one measured scenario check against the same check with only its declared subject replaced by committed bytes. The run must be a completed passing `ScenarioCheck` whose definition is still accepted, whose exact input snapshot is still current, and whose subject and budget declarations are nonempty. `before_ref` must be the full lower-case SHA of an available commit.

The operation uses the check's recorded input set as its immutable harness. Each sample gets a new temporary workspace and a new process. The candidate uses captured current subject bytes; the before side overlays only those subject paths from the named commit. All other declared input bytes remain identical. The Git overlay accepts regular blobs with mode `100644` or `100755`; absent files, symlinks, submodules, and unsupported modes make the request `UNSUPPORTED`. The check's own `dispatch.argv_for` builds the command. The operation does not accept a command, shell fragment, or arbitrary path from its caller.

Before and candidate runs alternate order (`before,candidate`, then `candidate,before`). Each report must parse through the approved scenario adapter, contain every required scenario exactly once and passing, and report exactly the declared budget measurements. Units and the `better` direction must agree across both sides and all pairs. A nonpositive before value makes relative regression undefined and stops the campaign as `INCONCLUSIVE`.

The result contains the run and check identity, the input snapshot digest and per-file captured-byte SHA-256 digests, the recorded report digest, SHA-256 digests and modes of both subject versions, environment metadata, each pair's order and both generated report digests, raw measurement values, and one summary per measurement. Regression is `(candidate-before)/abs(before)` for lower-is-better values and its negation for higher-is-better values. The summary reports the median paired regression and a deterministic 95% percentile-bootstrap interval over pair regressions. A declared `max_regression_pct` is `OVER_BUDGET` only when the interval is wholly above the threshold, `WITHIN_BUDGET` only when it is wholly at or below the threshold, and otherwise `INCONCLUSIVE`. A measurement without that clause is `NO_REGRESSION_BUDGET`. Top-level `MEASURED` means the requested paired campaign completed and passed its input/identity checks; it does not imply that each budget passed.

The operation refuses incomplete campaigns and returns `INCONCLUSIVE` with completed pairs retained for inspection. It rechecks the accepted check digest and every captured input before each process and after the campaign, so a changed harness or candidate checkout cannot silently mix into a result. These checks establish that this bounded campaign used the captured inputs; they do not prove repository-wide correctness or deterministic performance. In particular, `WITHIN_BUDGET` names only the declared paired statistical criterion. Scenario measurements remain observations produced by the approved driver on this machine and environment.

Limits are 10–20 pairs, 30–600 seconds for the total campaign, at most 1,000 input files, 1 MiB per file, 16 MiB total captured inputs and old subject bytes, and 8 MiB per report. A single process timeout is the smaller of the approved check timeout and remaining campaign time. Inputs and reports are bounded before reading; reports and repository inputs must be regular non-reparse-point files. The environment is fixed for the operation and its digest is reported, but external tools and services are not installed or virtualized by this operation.

For interpreting noisy measurements and outliers, see the [pyperf analysis guide](https://pyperf.readthedocs.io/en/latest/analyze.html). Its general statistical guidance does not validate a scenario driver or turn these observations into a performance guarantee.
